Documentation des Tests - Projet Metro 2025

Vue d'ensemble

Ce document décrit l'ensemble des tests implémentés pour valider les fonctionnalités du projet Metro 2025.

Exécution des tests

Compilation et exécution simple

make run-tests

Vérification mémoire avec valgrind

make test-memory

Compilation seule

make tests
./tests

Organisation des tests

Le fichier tests.c contient maintenant 10 suites de tests couvrant :

1. Tests de base (Tests 1-5)

Ces tests valident les fonctionnalités principales implémentées dans les exercices 1 et 2 :

  • Test 1 : Lecture des stations depuis un fichier CSV
  • Test 2 : Affichage des stations triées par latitude
  • Test 3 : Calcul des limites de zone (coordonnées NO et SE)
  • Test 4 : Création de l'ABR des stations
  • Test 4.1 : Recherche de stations dans l'ABR (case-insensitive)
  • Test 5 : Test des fonctions d'extraction de liste

2. Tests de cas limites (Test 6)

Validation du comportement avec des données limites :

  • Test 6.1 : Insertion dans une liste vide
  • Test 6.2 : Extraction sur liste vide
  • Test 6.3 : Calcul limites sur liste vide
  • Test 6.4 : Insertion en début de liste

Résultat attendu : 4/4 tests réussis

3. Tests de robustesse ABR (Test 7)

Validation de la robustesse de l'arbre binaire de recherche :

  • Test 7.1 : Recherche dans ABR vide
  • Test 7.2 : Construction ABR depuis liste vide
  • Test 7.3 : Recherche avec nom vide
  • Test 7.4 : Recherche avec caractères spéciaux (apostrophes)

Résultat attendu : 4/4 tests réussis

4. Tests de configuration invalide (Test 8)

Validation de la gestion des erreurs de configuration :

  • Test 8.1 : Fichier config inexistant
  • Test 8.2 : Destruction config NULL

Résultat attendu : 2/2 tests réussis

5. Tests CSV malformés (Test 9)

Validation de la gestion des fichiers CSV invalides :

  • Test 9.1 : Fichier stations inexistant
  • Test 9.2 : Fichier CSV vide
  • Test 9.3 : Fichier CSV avec lignes malformées

Résultat attendu : 3/3 tests réussis

6. Tests de gestion mémoire (Test 10)

Validation de la gestion des pointeurs NULL :

  • Test 10.1 : Destruction truc NULL
  • Test 10.2 : Destruction liste vide
  • Test 10.3 : Destruction liste_et_truc vide
  • Test 10.4 : Destruction ABR vide

Résultat attendu : 4/4 tests réussis

Ajout de nouveaux tests

Pour ajouter de nouveaux tests :

  1. Créer une nouvelle fonction de test dans tests.c
  2. Ajouter le prototype dans tests.h
  3. Appeler la fonction dans le main() de tests.c
  4. Suivre le même style de rapport (compteur tests_ok/tests_total)

Exemple :

void test_nouvelle_fonctionnalite() {
printf("11. Tests de nouvelle fonctionnalite\n");
int tests_ok = 0;
int tests_total = 0;
// Test 11.1: Description
printf(" Test 11.1: Description\n");
tests_total++;
// ... code du test ...
if (condition_reussie) {
printf(" OK: test reussi\n");
tests_ok++;
} else {
printf(" ERREUR: test echoue\n");
}
printf(" Bilan: %d/%d tests reussis\n\n", tests_ok, tests_total);
}

Recommandations

  1. Toujours exécuter les tests après modification du code
    make run-tests
  2. Vérifier les fuites mémoire régulièrement
    make test-memory
  3. Ajouter des tests pour chaque nouvelle fonctionnalité
  4. Tester les cas limites et les erreurs, pas seulement les cas normaux
